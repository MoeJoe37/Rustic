# PERF-01 first cross-engine report (M5 slice) — 2026-11-19

This is the first report of the cross-engine harness
([PERFORMANCE.md](../PERFORMANCE.md#cross-engine-gates)). At the M5 stage the
ratchet records ratios and sets no target. It measures Rustic's JS-09 corpus
in Rustic and in three JavaScript engine shells, and Rustic's DOM
microbenchmarks in Rustic alone.

## Setup

| Item | Value |
| --- | --- |
| Rustic | `feature` at `3d04368` plus this change, release build, `rustc 1.99.1` |
| Host | 13th Gen Intel Core i7-13650HX, x86-64, Linux 7.3.4 (Fedora), one core pinned with `taskset -c 2` |
| V8 | 15.0.245.2, embedded in Deno 2.9.8 (`deno run --quiet --v8-flags=--single-threaded`) |
| SpiderMonkey | 160.0.1 release `jsshell-linux-x86_64.zip` from `ftp.mozilla.org` |
| JavaScriptCore | WebKitGTK `jsc` bundle `327268@main`, built 2026-11-19 (WebKit publishes no versioned Linux shell) |
| Runs | 11 per cell. Each Rustic sample is a fresh agent (`js_bench --samples`); each shell sample is a fresh process |
| Size | `run(200000)` for the JS corpus, `run(20000)` for the DOM corpus |

Times exclude process start-up and source loading: every engine times the
one `run(size)` call with its own clock (`performance.now()`, or
`preciseTime()` in JavaScriptCore). Cells are the median in milliseconds
and a distribution-free 95% confidence interval of the median (the 2nd and
10th of 11 ordered samples). Every engine returned the same checksum for
every workload.

Reproduce with:

```sh
cargo build --release -p rustic-js --example js_bench -p rustic-engine --example dom_bench
taskset -c 2 python3 tools/cross_engine_bench.py \
    --rustic target/release/examples/js_bench --dom target/release/examples/dom_bench \
    --engine "V8=deno run --quiet --v8-flags=--single-threaded {file}" \
    --engine "SpiderMonkey=/path/to/js {file}" \
    --engine "JavaScriptCore=/path/to/jsc {file}" \
    --output report.md
```

## Reading the numbers

Rustic is a bytecode interpreter without a JIT; the three shells run their
full tiered JITs. Rustic is 4.9 to 22.9 times slower than the fastest engine
on these workloads: closest on JSON and property access, furthest on call-
and allocation-heavy code (`framework_diff`, `alloc_churn`, `closures`).
That matches the M12 plan (inline caches, shape lookup, collector pauses:
TD-95, TD-103, TD-104) and sets the baseline the M8 ratchet (at most 2.0)
starts from. No target applies at M5.
